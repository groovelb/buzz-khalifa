## 1. 한 줄 요약

> 초고층 빌딩이 어떻게 서는지를 글이 아니라 스크롤 한 번으로 따라 보게 하는, 부르즈 할리파 공정 해설 인터랙티브 지면.

태그라인: Burj Khalifa · A Study in Verticality

---

## 2. 배경과 목적

- **문제 또는 기회**: 초고층 빌딩의 공정은 기초, 코어, 세트백, 외피, 조명, 첨탑처럼 순서가 분명한데, 일반 독자가 만나는 자료는 완성 사진과 기록 수치뿐이다. 무엇이 먼저 서고 무엇이 나중에 붙는지는 사진 한 장으로 전달되지 않는다.
- **왜 지금, 왜 우리**: 공정은 본래 시간 순서를 가진 이야기이고, 웹의 스크롤은 시간 순서를 그대로 옮길 수 있는 유일한 조작이다. 읽는 속도가 곧 건설 속도가 되면 설명 없이도 순서가 몸에 남는다.
- **기대 효과**: 복잡한 구조 용어를 외우지 않고도 여섯 공정의 순서와 이유를 떠올릴 수 있다. 실제 현장 사진과 모형이 같은 자리에서 대조되어 추상적인 도해가 아니라 실제 건물의 일로 읽힌다. 완성 장면이 낮에서 밤으로 넘어가며 관람이 마무리된다.

## 3. 정체성

### 3.1 핵심 가치 (최대 3)

| 이름 | 한 줄 | 반대말 (하지 않는 태도) |
|---|---|---|
| Verticality (수직성) | 모든 장면이 위로만 자란다 | 사방으로 흩어지는 볼거리 |
| Legibility (가독성) | 한 번에 한 공정만 보여준다 | 전체를 한꺼번에 펼치는 도해 |
| Record (기록) | 해설에 수치와 기술 노트를 붙인다 | 감탄사로 채운 홍보 문구 |

### 3.2 태도 키워드 (최대 5, 단어만)

수직적 · 정밀함 · 에디토리얼 · 절제 · 기록적

### 3.3 포지셔닝 (선택)

| 축 | 우리의 선택 | 반대 축 |
|---|---|---|
| 장르 | 건축 저널의 연재 기사 | 관광 랜드마크 홍보 |
| 전달 방식 | 스크롤로 따라가는 공정 체험 | 텍스트 백과의 항목 열람 |
| 시각 언어 | 절제된 건축 도면 감각 | 실사 렌더의 과시 |
| 조작 | 읽기 속도가 곧 건설 속도 | 자유 시점 조작 도구 |

## 4. 사용자와 다루는 대상

### 4.1 사용자

| 이름 | 누구인가 | 무엇을 원하나 | 주/보조 |
|---|---|---|---|
| 건축 애호가 | 초고층 건축에 흥미가 있는 비전문 독자 | 순서가 보이는 쉬운 설명 | 주 |
| 건축 학습자 | 구조와 시공을 배우는 학생, 입문 실무자 | 단계별 구조 원리와 수치 | 주 |
| 연출 관람자 | 웹 연출 사례를 보러 온 방문자 | 웹 인터랙션 사례의 완성도 | 보조 |

비고: 세 행 모두 잠정이다. 원천에 사용자 정의가 없어 PRD의 교육 목표와 지면 톤에서 추론했다 (Q2).

### 4.2 다루는 대상

| 이름 | 식별자 | 한 줄 정의 | 만드는 주체 | 개수 |
|---|---|---|---|---|
| 공정 단계 | ConstructionStage | 번호, 제목, 해설, 기술 노트, 수치 한 벌 | 제작자 | 몇 개 |
| 구조 요소 | StructureElement | 한 공정에서 자라는 3차원 구조 부분 | 제작자 | 몇 개 |
| 티어 | Tier | 높이와 세 날개 치수를 가진 타워 한 켜 | 제작자 | 많음 |
| 시간대 | TimeOfDay | 읽기 진행에서 파생되는 낮과 밤 사이 상태 | 제작자 | 하나 |
| 공정 사진 | StagePhoto | 단계마다 붙는 실제 현장 사진 한 장 | 제작자 | 몇 개 |

비고:

- 개수 값은 하나 / 몇 개 / 많음이다. 공정 단계와 구조 요소, 공정 사진은 각각 여섯이고 티어는 스물넷이다.
- 읽기 진행도(스크롤 위치)는 화면을 그리는 UI 내부 상태로 보아 대상에서 뺐다. 시간대와 각 단계의 성장은 이 값에서 파생된다.

## 6. 범위와 성공 기준

- **포함**: 여섯 공정의 순차 관람, 단계별 해설과 기술 노트와 수치, 단계별 현장 사진, 읽기 진행에 따른 낮에서 밤으로의 변화, 완성 후 전체 조망
- **제외**: 회전·확대 같은 자유 시점 조작 · 목차나 단계 건너뛰기 내비게이션 · 실제 층과 부재 단위의 구조 정확도 · 계정과 저장 기능 · 공정 데이터의 실시간 갱신
- **제약**: 해설과 치수는 코드에 박힌 정적 데이터다 · 서버와 데이터베이스가 없다 · 조작은 읽기 진행 하나뿐이다 · 한 화면 안에서 전부 일어난다 (잠정)

성공 기준은 체류 지표가 아니라 순서의 기억을 우선한다.

| 성공 기준 | 확인 방법 |
|---|---|
| 관람 후 여섯 공정을 순서대로 떠올린다 | 관람 직후 회상 질문 (잠정, Q3) |
| 세트백이 왜 있는지 한 문장으로 말한다 | 과업 1 후 이유 질문 (잠정, Q3) |
| 조작 안내가 없어도 스크롤로 진행한다 | 첫 화면 관찰 기록 (잠정, Q3) |
| 모형과 현장 사진을 같은 공정으로 읽는다 | 과업 2 관찰 기록 (잠정, Q3) |
| 마지막 장면을 완성으로 인식하고 멈춘다 | 종료 지점 관찰 (잠정, Q3) |

비고: 포함과 제약의 근거는 코드 사실이다. 정적 데이터, 서버 호출 없음, 읽기 진행 외 입력 없음, 단일 화면을 확인했다.
